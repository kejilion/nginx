# kejilion.sh / KPanel 通用 Nginx 性能与安全规范

本规范约束官方 Nginx 基线、可选 WAF 扩展、依赖、新特性、共享模板及生态消费链路的持续迭代。适用于 kejilion.sh 和 KPanel 用户，覆盖直连、CDN 和混合部署。正式服是生态发布前的试点生产环境，公共默认值须同时通过独立通用场景验证；生产网站的特例不能成为所有用户的默认配置。

官方 Nginx 镜像是性能与安全基线；WAF 镜像在同一基线上验证规则检查的额外成本和保护能力。本规范中的 ModSecurity/CRS、审计和封禁要求按实际启用的组件适用，不要求普通 Nginx 用户安装 WAF。现行操作入口与已完成验证见 [README.md](README.md)，后续任务从本规范继续，不另建平行规则。

## 既有兼容与安全原则

1. 面向 kejilion.sh、KPanel 的所有用户；域名、地址、凭据、白名单和业务例外属于部署配置，不进入公共默认值。
2. 两端复用由 kejilion.sh 声明的同一份配置来源、管理入口和资源布局，不维护平行规则或影子状态。
3. 同时支持直连、Cloudflare、明确配置的其他 CDN/可信反代及混合部署。
4. 覆盖静态站、CMS/WordPress、论坛、REST API、鉴权、Webhook、上传下载、WebSocket/SSE、多站点和共享 NAT；应用专属例外必须精确且可审计。
5. 逐环节查阅实际版本的组件及依赖官方文档：CDN、真实 IP、Nginx、TLS/OpenSSL、ModSecurity、OWASP CRS、Fail2Ban、日志和封禁后端。核对默认值、版本兼容、上游限制及弃用项；验证组件组合后的行为。
6. 重要调优项保留官方来源、适用版本、选择理由、余量依据及原始验证结果。当前配置和第三方教程不能替代官方依据。
7. 根据正常业务、实测峰值和机器容量保留请求突发、连接、请求体、上传、超时及资源余量；所有配额有边界、可观测、可调整。攻击评分采用经验证的安全基线，误报以精确排除处理。
8. 客户端身份只接受明确可信代理提供的来源信息；直连伪造头无效；不自动信任整个私网、Docker 地址段或任意来源。
9. 限流、异常累计和封禁按站点与真实客户端隔离，防止跨站及共享出口误伤。
10. 单次请求拦截与持续滥用封禁分离。普通业务 401/403/404/429 不作为独立封禁依据；只消费明确、可信的防御事件。
11. 封禁有范围、上限、有效期、记录和解封入口；保护代理节点及本机基础设施，避免账号范围的默认 CDN 封禁。
12. 通用基线与业务配置档分离。例外限定到站点、路径、参数和规则；检测模式和灰度是可管理状态，不能冒充已经阻断。
13. 安装、检测、启停、状态诊断、策略调整、封禁管理、更新、回滚和卸载形成闭环；两端回读真实资源状态。
14. 变更保留基线，原子写入、语法检查、应用、回读；失败保留或恢复上一份有效配置，升级和卸载保护用户自定义内容。
15. 日志、封禁、状态、临时文件及刷新频率有界；验证 CPU、内存、磁盘和延迟影响，不以增加配额掩盖无界资源问题。
16. 使用通用矩阵与试点生产验证：正常业务、恶意请求、伪造 IP、CDN/直连、多站点隔离、失败注入、重启、升级和回滚。攻击、压力和故障注入使用隔离环境，避免再次封禁办公出口或影响真实用户。
17. 验证通过后才更新公共默认模板；同步同一套已验证版本、摘要、兼容条件、迁移和回滚方式。
18. 核对原生脚本入口、下载来源、KPanel 共享适配及受管脚本依赖；只有生态消费链路有证据，才宣告生态交付完成。
19. 区分已验证、未验证、检测中、待发布及受限制状态；不以正式服正常代替全部验收，不声称 WAF 配置等于 ASVS 整体符合性。
20. 历史整站关闭 WAF 视为待迁移兼容问题，不复制为公共永久豁免；逐项定位误报，形成业务配置档和精确排除，以正常业务通过且攻击反例仍阻断作为开启拦截的条件。检测模式是过渡状态，不能替代精细调优。
21. 优先沿用现有 Cloudflare、Nginx、ModSecurity/CRS、Fail2Ban 组件和链路；新增常驻服务、替换封禁后端等架构变更单独评估，经明确确认后才能实施或纳入公共默认方案。

## 官方新特性与依赖准入

每次接纳 Nginx、OpenSSL、基础镜像、模块、ModSecurity、连接器或 CRS 的新版本，都应核对官方变更记录、安全公告、弃用项和依赖条件。安全修复优先按影响范围处理；功能采用以收益、兼容性和维护成本为依据，不能以“最新”替代判断。已有版本相同的前后比较不能记作内核升级收益。

每项候选记录以下信息，可纳入现有发布记录，无须另建文档系统：

上游升级不能依赖定制引擎性能补丁：只有精确满足已验证源码条件且补丁预检通过时启用可选优化；新版本、源码变化或补丁不适用时自动保留官方源码继续构建，不因性能优化阻断安全升级，也不强套旧补丁。镜像和正式构建产物必须记录实际 `optimized` / `upstream` 状态，退回官方实现时允许失去该项加速，不得假称继承了性能收益。新版本继续运行公共兼容和安全门禁；实际不兼容仍应阻止发布。上游已等价修复时优先移除本地补丁，只有收益与维护成本值得时才另行适配优化，不要求每次升级人工修补。同步逐项比较共享包显式指令、CRS 规则 ID/标签/集合、插件和加载顺序与官方新默认；继续加载新规则不代表官方新增配置或功能已生效。明确记录继承、覆盖、按需采用和暂缓项，检测语义与通用业务验证通过后才能升级。

| 项目 | 必需内容 |
| --- | --- |
| 来源与身份 | 官方文档/公告链接、核对日期、引入版本、镜像 digest、编译与运行时依赖；Nginx 动态模块还需核对 ABI/构建参数 |
| 场景与边界 | 对静态站、CMS、API、上传、流式连接、直连和 CDN 分别有什么作用，客户端/上游/内核需要什么条件 |
| 实际状态 | 分别记录“版本支持”“已编译”“配置启用”“链路实际使用”“有专项验证收益”；不能互相替代 |
| 采用结论 | 待评估、隔离验证、生产试点、公共默认、按需配置、暂缓或不适用；写明理由、下一步证据和回退办法 |

浏览器到 CDN、CDN 到源站、源站到应用上游应分别判断协议和收益。CDN 边缘启用 HTTP/3，不代表源站链路使用 HTTP/3；配置有 `http3 on` 也不代表客户端已经协商成功。由依赖库或内核决定的能力必须实测，不能只根据 Nginx 版本推断。

TLS 证书压缩、103 Early Hints、请求体提前读取、kTLS、0-RTT 等功能先进入候选评估，确认协商、应用配合、资源成本及安全边界后再决定默认或按需启用。认证、缓存隔离、来源信任、请求解析与重放风险不能为性能让步；证书缓存也须区分变量路径证书和普通静态证书的实际适用性。

## 通用参数与余量

1. 每项参数记录官方默认值、当前公共值、正式服原值、候选值、资源含义、适用范围和测试结果。分开比较“旧公共模板→新模板”和“生产原配置→新配置”，不混用基线。
2. 通用默认面向多数网站；特殊业务使用明确的站点配置档和覆盖项。CSP、缓存鉴权、超大上传、流式超时、上游证书信任等按业务配置，不把试点域名、证书或例外写进公共模板。
3. 缓冲池上限、共享区、每请求分配、连接数、HTTP/2/3 流数与磁盘临时文件分别核算。配置容量不等于常驻内存；上传上限、单 IP 限流值也不等于整机可承载量。
4. 根据代表性正常峰值，至少预留 40% CPU 容量，并为同机应用、握手、突发和磁盘写入单独留预算；内存、临时盘、日志和文件描述符也要有余量。机器或业务变化后重新测量，不以调高限制掩盖饱和。
5. 余量必须有依据。1.0.5 的 gzip/output 池总量选为官方默认约四倍，是该轮测试支持的选择，不是后续参数统一乘四的公式，也不是所有用户的容量保证。
6. 性能调优同时报告吞吐、CPU、匿名/总内存、延迟、磁盘及日志成本。开始测试前明确接受范围；出现吞吐或延迟退步时说明换来的收益并作采用决定。1.0.5 的取舍不能作为今后自动允许同等回退的额度。

## 持续迭代闭环

业务兼容调优先还原完整请求链和协议语义，再按通用行为分类。反复出现的框架机制应优先形成有前置条件、授权边界和攻击反例的公共守卫；不能仅凭存在某个头、字段或业务路径判定攻击，也不能因它常见就免检。应用专属差异才使用精确配置档和排除。验证既要确认返回状态，也要确认上游实际执行的含义；完整能力不能证明、配置发生漂移或第三方认证逻辑不透明时保守处理，不自动扩大权限。

一轮迭代依次经过以下步骤；文档、低风险配置和镜像/协议变更按实际影响选择验证强度，不机械重跑所有测试。

1. **盘点与冻结基线**：确认真实链路、镜像与依赖、挂载配置、站点开关、CF/其他代理信任、封禁动作和生态下载来源；记录已发布版本、生产实际值与恢复点，保留其他任务期间新增的提交。
2. **官方核对与候选选择**：按上节更新新特性与安全修复清单，记录采用/暂缓理由，设定收益、资源、兼容及安全验收条件。每轮聚焦一个可解释的变更集。
3. **隔离验证**：使用固定镜像和源码，在相同资源、数据与负载下比较；验证正常业务、攻击反例及必要失败路径。压力、恶意样本和故障注入只在隔离环境执行。
4. **独立复核与试点**：运行时配置、镜像、依赖或协议变更经独立复核后，在已授权正式服备份、小步应用、语法检查、重载/就绪核验及正常业务观察；出现相关异常即停止推广并恢复可用版本。观察时长由连接生命周期、负载和风险决定，不虚构长期稳定性。纯文档变更只做相应内容、来源和链接核对。
5. **同一产物发布**：试点无误后同步公共模板、镜像及原生脚本固定版本/摘要；KPanel 只有契约或消费链路确需变更时才纳入发行。正式镜像发布复用已验证的同一批构建产物，禁止验证后重建不同产物直接替换。
6. **公开与消费回读**：回读远端提交/tag、公开配置字节、各架构镜像配置及 RootFS；验证消费者实际下载、缓存校验、升级和回滚。区分公共新入口与生产仍安装的旧 CLI，不能用临时脚本验证声称已替换系统入口。
7. **记录与触发下一轮**：保存结果、失败尝试、取舍、未覆盖项及回滚顺序。组件发布/安全公告、误报或封禁异常、错误率/延迟/资源趋势变化、业务类型及容量变化触发下一轮评估；重复同类问题应沉淀为通用修复或精确配置档。

持续迭代不等于后台自动升级或自动发版。当前会话已明确授权的范围可以连续完成，不逐步骤重复确认；未来计划外架构变更、生产部署及外部高风险写入仍须遵守届时的用户授权。没有触发实际后台任务时，不声称已经建立定时监控。

## 验证与发布记录要求

| 受影响部分 | 必需证据 |
| --- | --- |
| 共同 Nginx 配置 | 官方镜像和 WAF 镜像的同版本比较；WAF Off/On 功能及资源差异，涉及检测行为时补 Detect；区分配置站点数与实际活跃站点数 |
| 正常业务与安全 | 按变更覆盖静态/PHP/反代、鉴权/Cookie/缓存、API/Webhook、上传、Range、WebSocket/SSE/gRPC；恶意反例仍拦截，正常 401/403/404/429 不成为误封依据 |
| 身份与多租户 | 直连、Cloudflare、明确可信的其他代理/混合模式、伪造转发头、多站点和共享 NAT；不以模拟代理身份宣称完成真实 CDN 性能测试 |
| TLS/HTTP 新特性 | 涉及项必须有实际协议协商、TLS 新握手/恢复、TTFB 与整体下载时间的对应测试；HTTP/3、证书压缩和 Early Hints 不能只凭语法检查验收 |
| 公平性能比较 | 固定 CPU/worker、内存/swap、发压器与源站预算；控制连接分布、冷热缓存及执行顺序，必要时反序复测；确认发压器或上游没有先成为瓶颈 |
| 响应与资源真实性 | 正常状态和有效响应数、正文完整性、协议/压缩、错误/漏发、CPU/内存趋势、OOM/日志/磁盘预算；拒绝响应不计入业务吞吐，小样本不能承诺稳定 P99 |
| 更新与恢复 | 官方/WAF、旧共享包、新安装和受管旧基线；三方合并保留定制、CF 模式及开关，失败恢复确切配置/镜像，按顺序处理相互依赖的恢复点 |
| 架构与分发 | 声明支持的架构做正式构建与兼容检查；性能未实测的架构明确标注。源码 pin、固定包文件摘要、公开镜像 digest 和实际消费结果相互对应 |

发布记录至少包含：目标与范围、官方来源/核对日期、前后版本/参数和余量、特性实际状态、原始证据位置与摘要、通过/失败/跳过及限制、生产观察、独立复核、源码/模板/脚本 pin、镜像与各架构身份、发布结果和精确恢复点。先区分已验证事实、采用判断与待办，才宣告相应范围完成。原始私有配置、凭据和审计正文不进入公共记录。

固定配置包中只保留声明的文件，Python 诊断/管理入口使用 `-B` 避免生成 `__pycache__` 污染严格校验的缓存。发现额外内容时不放宽来源校验：先核验正式文件与所有权，再将确认的派生缓存移入私有恢复目录，保留证据后重验消费入口。

## 官方依据

- [Nginx realip](https://nginx.org/en/docs/http/ngx_http_realip_module.html)：信任明确的代理；保留原始连接地址。
- [Nginx 请求限流](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)：按 key 计数、突发、检测模式和明确的拒绝状态。
- [Nginx 连接限制](https://nginx.org/en/docs/http/ngx_http_limit_conn_module.html)：并发与 HTTP/2、HTTP/3 的计数语义。
- [ModSecurity v3](https://github.com/owasp-modsecurity/ModSecurity/wiki/Reference-Manual-(v3.x))：规则阶段、请求体限额、检测模式、审计及事务控制。
- [OWASP CRS 异常评分](https://coreruleset.org/docs/2-how-crs-works/2-1-anomaly_scoring/)：PL 与阈值独立，目标入站阈值 5、出站阈值 4；通过精确排除处理误报。
- [OWASP CRS 误报调优](https://coreruleset.org/docs/2-how-crs-works/2-3-false-positives-and-tuning/)：优先应用排除包与精确运行期排除，保留其他规则；避免误报日志泄露合法业务敏感输入。
- [Nginx 代理头继承](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header)及[子请求访问检查](https://nginx.org/en/docs/http/ngx_http_auth_request_module.html)：按完整有效作用域迁移代理头，组合访问控制；已有自定义认证不可静默覆盖。
- [Cloudflare 来源恢复](https://developers.cloudflare.com/support/troubleshooting/restoring-visitor-ips/restoring-original-visitor-ips/)及[官方地址 API](https://developers.cloudflare.com/api/resources/ips/methods/list/)：CIDR 与客户端头的信任边界。
- [Fail2Ban](https://github.com/fail2ban/fail2ban/wiki)：基于可信日志的过滤、动作、计数和封禁生命周期。
- [Nginx 变更记录](https://nginx.org/en/CHANGES)与[安全公告](https://nginx.org/en/security_advisories.html)：逐版本确认新增能力、修复范围、弃用项及升级必要性。
- [Docker Official Image: Nginx](https://github.com/nginx/docker-nginx)：官方镜像来源及构建；共同基线与可选 WAF 扩展分别核验。
- [Nginx gzip 缓冲](https://nginx.org/en/docs/http/ngx_http_gzip_module.html#gzip_buffers)、[输出缓冲](https://nginx.org/en/docs/http/ngx_http_core_module.html#output_buffers)与[TLS 缓冲](https://nginx.org/en/docs/http/ngx_http_ssl_module.html#ssl_buffer_size)：默认值、适用范围和资源含义。
- [Nginx 安全头继承](https://nginx.org/en/docs/http/ngx_http_headers_module.html#add_header_inherit)：merge 的追加语义及作用域；与去重、应用策略分别处理。
- [Nginx TLS 证书压缩](https://nginx.org/en/docs/http/ngx_http_ssl_module.html#ssl_certificate_compression)和[证书缓存](https://nginx.org/en/docs/http/ngx_http_ssl_module.html#ssl_certificate_cache)：依赖条件、协商与证书类型边界。
- [Nginx Early Hints](https://nginx.org/en/docs/http/ngx_http_core_module.html#early_hints)和[请求体提前读取](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_body_early_read)：上游配合条件和模块兼容限制。
- [Nginx HTTP/3](https://nginx.org/en/docs/http/ngx_http_v3_module.html)及[Cloudflare HTTP/3](https://developers.cloudflare.com/speed/optimization/protocol/http3/)：源站、CDN 与客户端链路分别核验。
- [Nginx HTTPS 上游校验](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_ssl_verify)与 [OpenSSL 安全公告](https://openssl-library.org/news/vulnerabilities/)：信任、依赖漏洞及修复适用范围。

WAF 不替代应用鉴权、授权、漏洞修复和上游容量防御。具体默认值、适配版本及验证结果随实现记录，不把尚未验证的设计写为通过。
